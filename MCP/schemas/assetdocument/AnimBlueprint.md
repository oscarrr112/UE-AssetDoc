# AnimBlueprint Profile

Classes: /Script/Engine.AnimBlueprint

Class `/Script/Engine.AnimBlueprint`. Body keys: `ParentClass`, `TargetSkeleton`, `Template` (bool, immutable after creation), the UBlueprint members (`ImplementedInterfaces`, `Variables`, `ClassDefaults`, `EventDispatchers`), the graph regions `UbergraphPages` / `FunctionGraphs` / `MacroGraphs` (same node format as UBlueprint) plus `AnimGraph` and `AnimLayers` (animation nodes `Anim:<Kind>`, state machines, layers), and the settings `Preview`, `SyncGroups`, `ParentAssetOverrides`, `Thumbnail`. `Components` and `Timelines` are accepted only as `[]`. Omitted = keep; present = complete region. Class Settings are top-level `Properties`. New assets need `ParentClass` and `TargetSkeleton` (or `Template: true`).

Animation node settings: the `Properties` of an `Anim:` node (`Node.PlayRate`, `Node.bLoopAnimation`, `ShowPin.<Property>`, `Bindings`, ...) are its complete Details settings. A setting the node leaves out is the node's default (the Details panel's reset to default), so deleting a setting from the document resets it, and a node without `Properties` has the defaults; a pin the document links or binds stays shown. Extract writes every non-default setting: to keep one, keep it in the document. An `FInstancedStruct` setting (a Chooser Player node's inline chooser) is `{"Struct": "<struct path>", "Properties": {<fields>}}` or `null`: the same struct edits the held value (omitted fields keep theirs), another struct starts from its defaults, and a `BaseStruct` restriction applies. A blend space node's `Samples` and a layer output's `LayerGroup` are structural and are not reset by omission. `SM:` nodes (states, conduits, aliases, transitions) follow the same rule against a newly placed node: an omitted setting (`CrossfadeDuration`, `bAlwaysResetOnEntry`, an alias's `AliasedStates`, ...) is reset to the new node's value (a new transition has `bAllowInertializationForSelfTransitions: true`); a transition's `LogicType` follows its `BlendGraph`.

Node functions (Details > Functions): `Functions.OnInitialUpdate`, `Functions.OnBecomeRelevant`, `Functions.OnUpdate` name the bound function: a function of the Anim Blueprint by name (it must be thread safe and take the picker's `(Context, Node)` parameters; one made in the same document binds before it is compiled), a function library's as `"<class path>:<function>"`; `""` unbinds. Left out, a binding is kept. A refused name lists the functions the node can bind.

`Bindings` entries: `{"Path", "OnlyUpdateWhenActive"?, "ContextId"?}`. `ContextId` is the binding's call site (`"UnBatched_ThreadSafe"`, `"Batched_WorkerThreadPreEventGraph"`, `"Batched_WorkerThreadPostEventGraph"`, `"Batched_GameThreadPreEventGraph"`, `"Batched_GameThreadPostEventGraph"`; `""` is Automatic, omitted on extract); an entry without it keeps the call site the binding has. An array element's pin binds by the pin's name (`"BlendTime_0"`); a binding of the whole array and one of its elements replace each other.

Property Access node (a K2 node in any graph of the Anim Blueprint): `Properties.Path` is the picked path, dotted (`"GetOwningActor.Velocity"`, a segment can be `Array[2]`), `""` for none; it must resolve on the Anim Blueprint. `Properties.ContextId` is the node's call site (same names as above, `""` Automatic). Left out, each is kept.

Linked Anim Graph and Linked Anim Layer nodes: `"ShowPin.<Variable>"` toggles the input pin of a variable of the linked class or layer (Details > Inputs). Extract writes a toggle only where it differs from the editor's default (an instance-editable variable shows); left out, a toggle is kept.

Shared transition rules: a transition's `Properties.SharedRules` names the shared rule it uses (context menu Promote To Shared / Use Shared), `SharedCrossfade` the shared crossfade settings; `""` stops sharing (the transition gets its own copy). A new name promotes the transition's rule; an existing name makes the transition use that rule. Extract writes the shared rule's `Graph` on one transition of the group only (the others carry the name alone); two transitions of one group that both carry a `Graph` are refused (`Graph.SharedRuleGraph`). A transition that joins a group takes the group's rule: leave its `Graph` out. Renaming a group re-creates its rule from the document. Left out, the sharing is kept. `SharedRules` alone keeps the transition's blend settings (the editor's Use Shared also takes the group's shared crossfade); write `SharedCrossfade` to share those too. A shared rule belongs to one state machine: using a name another state machine shares, or a `Graph` for one name in two state machines, is refused (`Graph.SharedRuleAcrossStateMachines`); a group the editor made across state machines is kept as it is.

Control Rig node (`Anim:ControlRig`, `Node.ControlRigClass`): the rig's public variables and animatable controls are input pins only once exposed, as in Details > Input ("use pin"): `"ShowPin.<Variable>": true` exposes one (also a variable the rig got after the node was made), so a link to it can follow in the same document; left out, the pin is hidden. An unknown name is refused with the rig's public variables and controls listed (a variable must be Public in the rig).

State machine transitions: `{"Id", "Action": "SM:Transition", "From": "<state id>", "To": "<state id>", "Graph"?, "BlendGraph"?, "Properties"?}`. Two or more transitions between the same pair of states are allowed, as in the editor. An extracted transition carries its `NodeGuid`, which identifies it; a transition written without `NodeGuid` is matched to the live transitions with the same `From`/`To` in list order (the first such entry to the first live one, and so on). To remove or edit one specific duplicate, edit an extracted document (it keeps each `NodeGuid`). The `Id` of a transition is local to the document; changing it changes nothing.

Getters of a source (Time Remaining (ratio), Current Time (ratio), State Weight, Get Relevant Anim Time Remaining, ... in transition rules and anim graphs) are keyed by their function and the source they read, as the getter's title names it: `K2:AnimGetter:/Script/Engine.AnimInstance:GetInstanceAssetPlayerTimeFromEndFraction@Jog_Fwd`. The source is the asset of an asset player (`@Jog_Fwd` for a Sequence Player of Jog_Fwd), the name of a state or alias (`@Idle`), a transition `@<from state>-><to state>`, or the name of a state machine (`@Locomotion`). A new getter is placed through the palette action of that source the graph offers: in a transition rule, the players and state of the transition's previous state. Two sources of the same name offered in one graph (the same asset played twice in the previous state) fail with `Graph.ActionAmbiguous`, listing the keys. A source whose name holds `:`, `@` or `#` is keyed without it. The older key without `@<source>` still names a getter kept by its `NodeGuid`, a getter that is the only one of its function in the graph on both sides, and, for a new node, the only such getter the graph offers; extract keeps it where it was applied that way and names one getter. Changing a player's animation asset changes its getters' keys. A getter kept by its `NodeGuid` whose key names another source is moved to that source (the getter of that source replaces it) when the graph has it; when it does not (the source was renamed or replaced since the document was written), the apply is refused with `Graph.GetterSourceMissing`, naming both the document's source and the node's current one.

Layout: anim nodes take `Position` like Blueprint nodes. `"Layout": "Auto"` (see Blueprint) works on `AnimGraph`, each `AnimLayers` entry and every nested graph (a state machine's, state's, transition's `Graph`, a `BlendGraph`, a sample `Graph`): it lays out the nodes without a `Position` (data flows right to the Output pose; states and conduits are placed like other nodes). Diff reports it at that graph's path, e.g. `/Body/AnimGraph/Nodes/0/Graph/Layout`. Node sizes of anim graphs are estimated, not measured.

Validate checks node keys, pins and links of the K2 graphs (`UbergraphPages`, `FunctionGraphs`, `MacroGraphs`) as for a Blueprint Class (see Blueprint), on the existing Anim Blueprint or (a new one) on a transient template Anim Blueprint of its `ParentClass`; the anim graphs are checked by Apply.

Open editor: an apply works while the Anim Blueprint is open. The editor shows the result (graphs, My Blueprint, tabs of removed graphs close; the Persona preview runs the recompiled class), also after a failed apply.
