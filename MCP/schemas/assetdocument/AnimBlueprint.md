# AnimBlueprint Profile

Classes: /Script/Engine.AnimBlueprint

Class `/Script/Engine.AnimBlueprint`. Body keys: `ParentClass`, `TargetSkeleton`, `Template` (bool, immutable after creation), the UBlueprint members (`ImplementedInterfaces`, `Variables`, `ClassDefaults`, `EventDispatchers`), the graph regions `UbergraphPages` / `FunctionGraphs` / `MacroGraphs` (same node format as UBlueprint) plus `AnimGraph` and `AnimLayers` (animation nodes `Anim:<Kind>`, state machines, layers), and the settings `Preview`, `SyncGroups`, `ParentAssetOverrides`, `Thumbnail`. `Components` and `Timelines` are accepted only as `[]`. Omitted = keep; present = complete region. Class Settings are top-level `Properties`. New assets need `ParentClass` and `TargetSkeleton` (or `Template: true`).

Animation node settings: the `Properties` of an `Anim:` node (`Node.PlayRate`, `Node.bLoopAnimation`, `ShowPin.<Property>`, `Bindings`, ...) are its complete Details settings. A setting the node leaves out is the node's default (the Details panel's reset to default), so deleting a setting from the document resets it, and a node without `Properties` has the defaults; a pin the document links or binds stays shown. Extract writes every non-default setting: to keep one, keep it in the document. A blend space node's `Samples` and a layer output's `LayerGroup` are structural and are not reset by omission. `SM:` nodes (states, conduits, aliases, transitions) follow the same rule against a newly placed node: an omitted setting (`CrossfadeDuration`, `bAlwaysResetOnEntry`, an alias's `AliasedStates`, ...) is reset to the new node's value (a new transition has `bAllowInertializationForSelfTransitions: true`); a transition's `LogicType` follows its `BlendGraph`.

Control Rig node (`Anim:ControlRig`, `Node.ControlRigClass`): the rig's public variables and animatable controls are input pins only once exposed, as in Details > Input ("use pin"): `"ShowPin.<Variable>": true` exposes one (also a variable the rig got after the node was made), so a link to it can follow in the same document; left out, the pin is hidden. An unknown name is refused with the rig's public variables and controls listed (a variable must be Public in the rig).

State machine transitions: `{"Id", "Action": "SM:Transition", "From": "<state id>", "To": "<state id>", "Graph"?, "BlendGraph"?, "Properties"?}`. Two or more transitions between the same pair of states are allowed, as in the editor. An extracted transition carries its `NodeGuid`, which identifies it; a transition written without `NodeGuid` is matched to the live transitions with the same `From`/`To` in list order (the first such entry to the first live one, and so on). To remove or edit one specific duplicate, edit an extracted document (it keeps each `NodeGuid`). The `Id` of a transition is local to the document; changing it changes nothing.

Layout: anim nodes take `Position` like Blueprint nodes. `"Layout": "Auto"` (see Blueprint) works on `AnimGraph`, each `AnimLayers` entry and every nested graph (a state machine's, state's, transition's `Graph`, a `BlendGraph`, a sample `Graph`): it lays out the nodes without a `Position` (data flows right to the Output pose; states and conduits are placed like other nodes). Diff reports it at that graph's path, e.g. `/Body/AnimGraph/Nodes/0/Graph/Layout`. Node sizes of anim graphs are estimated, not measured.

Validate checks node keys, pins and links of the K2 graphs (`UbergraphPages`, `FunctionGraphs`, `MacroGraphs`) as for a Blueprint Class (see Blueprint), on the existing Anim Blueprint or (a new one) on a transient template Anim Blueprint of its `ParentClass`; the anim graphs are checked by Apply.

Open editor: an apply works while the Anim Blueprint is open. The editor shows the result (graphs, My Blueprint, tabs of removed graphs close; the Persona preview runs the recompiled class), also after a failed apply.
