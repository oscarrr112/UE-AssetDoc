# Niagara reference: Scripts and scratch pads

A script asset's Body (and each `ScratchPads` entry, plus its `Name`) is the script editor:

```jsonc
"Body": {
  "Usage": "Module",                                   // Module | Function | DynamicInput (pads: Module | DynamicInput)
  "Settings": {"Category": "Forces", "Description": "...", "ModuleUsageBitmask": ...},   // script Details
  "Versions": [{"Number": "1.0", "Guid": "...", "Exposed": true, "ChangeDescription"?, "Deprecated"?, "DeprecationMessage"?, "Visible"?}],
  "Parameters": [{"Name": "Module.Strength", "Type": "float", "Default": 1.0, "Meta": {"Description": "..."}},
                 {"Name": "Particles.Velocity", "Type": "Vector", "DefaultMode": "FailIfPreviouslyNotSet"}],
  "Graph": {
    "Nodes": [{"Id": "InputMap", "Action": "Niagara:Input:InputMap", "Position": [0, 0]},
              {"Id": "Get", "Action": "Niagara:MapGet", "Position": [200, 0], "Pins": {"Outputs": [{"Name": "Module.Strength", "Type": "float"}]}},
              {"Id": "Orbit", "Action": "Niagara:CustomHlsl", "Comment": "...", "Pins": {"Inputs": [{"Name": "Amount", "Type": "float"}], "Outputs": [{"Name": "Result", "Type": "float"}]},
               "Properties": {"CustomHlsl": "Result = Amount * 2;"}}, ...],
    "Links": [{"From": "Get:Module.Strength", "To": "Orbit:Amount"}, ...],
    "PinDefaults": {"Mul:B": "2.0"}}}
```

- Node `Id`s are the editor's object names (a new node is renamed to its `Id`). Actions: `Niagara:Function:<script path>`, `Niagara:Op:<op>` (e.g. `Numeric::Mul`), `Niagara:MapGet`, `Niagara:MapSet`, `Niagara:Input:<parameter>`, `Niagara:Output`, `Niagara:CustomHlsl` (text in `Properties.CustomHlsl`), `Niagara:StaticSwitch`, `Niagara:Select`, `Niagara:If`, `Niagara:Reroute`, `Niagara:Comment`, `Niagara:DataInterfaceFunction:<class>:<function>`, ...; `graph.actions.enumerate.v1` lists the graph's menu. `Pins` lists the pins added with a node's Add pin (Map Get / Set parameters, custom HLSL inputs / outputs) per direction it states, in order; a new pin needs a `Type` (the type tokens above) unless the graph already has that parameter. `Version` on a function call: the called script's version (guid or `"M.m"`; omitted = its exposed version). Custom HLSL pin names avoid HLSL words (`In`, `Out`: `Niagara.InvalidPinName`). The If node, the Usage Selector and VM fast-path calls (`Niagara:Function:Signature:*`) are read but cannot be added (the menu does not offer them: `Graph.ActionNotFound`); nor can deprecated data interface functions (`Niagara.DeprecatedFunction`). `Niagara:Input:<name>` not in the menu makes a new parameter input named `<name>` (as Add Parameter / Promote to Parameter); its `Properties` (`Input` name and type, `Usage`, `ExposureOptions`, `CallSortPriority`) are its Details. A type in `Pins` on a numeric pin is the pin's Convert Numeric To (an op or function call without an Add pin lists `Pins` when its numeric pins are typed). A static switch's `Properties.InputParameterName` is its parameter (the Details name box) and `SwitchTypeData` its type (Bool, Integer, Enum with `Enum`). A function call's `Properties.PropagatedStaticSwitches` (`[{Name, PropagatedName?}]`, complete) are its Details' Propagated Static Switch Values. A data interface function's `Properties.FunctionSpecifiers` are the specifier values shown on the node (every specifier the function has). A Map Get's default value pin is named after its output pin (`"PinDefaults": {"Get:Module.Strength": "2.0"}`) and is authored only when the parameter's `DefaultMode` is `Custom` (otherwise it shows the parameter's `Default`). An output node's outputs (functions, dynamic inputs) are its `Properties.Outputs`.
- `Graph` is complete when listed: nodes, links and pin defaults left out are removed / reset. Node `Properties` are sparse (listed values are written; read as differences from a new node, comments included). `Position` omitted keeps the node where it is (new nodes are placed automatically); `Comment` omitted = none. A new script keeps the nodes the New-asset factory made when the document lists one node per action of them under any `Id` (e.g. the input map, Map Get / Set and output).
- `Parameters` are the graph's parameters (its Map Get / Set pins and static switches); a listed one states that parameter's Details: `DefaultMode` (omitted = `Value`; `Binding` with `DefaultBinding`, `Custom`, `FailIfPreviouslyNotSet`), `Default` (mode `Value`; omitted = kept), `StaticSwitchDefault` (omitted = kept), `Meta` (complete: omitted = the default metadata). Unlisted parameters keep their Details; a parameter the graph does not use is refused (`Niagara.ParameterNotReferenced`), its type is its pins' type (`Niagara.ParameterType`). Parameters no pin uses any more leave the list, as the next load would do.
- `Settings` omitted keeps them; listed, they are complete (left out = default). The asset's other Details (`ValidationRules`, `PreviewMoviePath`) are top-level `Properties`.
- `Usage` is set when the script is created (`Action: Create`; the New-asset factory of that usage makes the starting graph) and cannot change (`Niagara.UsageImmutable`).
- `Versions` (the version menu): listed = complete. A new `Number` adds a version (a copy of the nearest lower one), `Exposed: true` exposes one, versions left out are deleted (never the exposed one or 1.0: `Niagara.VersionNotDeletable`); `[{"Number": "1.0"}]` enables versioning. With versioning, the other keys describe the exposed version. Editing the version that is exposed before the apply affects every user of the script and is refused (`Niagara.ExposedVersionEdit`, naming loaded users) unless the Body has `"EditExposedVersion": true`; or add a new version and expose it in the same document.
- The apply compiles the script (the script editor's Compile): errors it did not have before fail the apply at the node's `Graph/Nodes/<n>` path (`Niagara.CompileFailed`) and roll it back. Then, as the editor's Apply, loaded assets that call the script refresh and recompile (`Niagara.DependentsUpdated` warning lists them; they stay unsaved). A loaded user with unsaved changes refuses the apply before any change (`Niagara.DependentHasUnsavedChanges`): save or discard it first. A script open in its editor is closed for the apply and reopened (`Niagara.EditorReopened`); edits there not applied yet (Apply enabled) refuse the apply before any change (`Niagara.OpenInEditorUnsavedEdits`). The script editor cannot close without asking: `asset_editor` `apply_editor` applies them; to drop them, `apply_editor`, `close`, then `reload_assets` with `force: true`.

Scratch pads (system `ScratchPads`, emitter `ScratchPads`):

- The system's list is complete: a new `Name` adds a scratch pad (the Scratch Pad panel's "+", `Usage` `Module` or `DynamicInput`), `RenamedFrom` renames one, a pad left out is deleted after the stacks stop using it. Order is not authored.
- Renaming a pad renames the modules that call it, as the panel's rename does: the same document names those modules after the new pad (`"Name": "Swirl2", "Script": "ScratchPad:Swirl2"`).
- An emitter's pads are edited in place but cannot be added, removed or renamed from a system (`Niagara.ScratchPadScope`; they come with the emitter asset, whose own `ScratchPads` list is complete like the system's).
- Each pad's `Usage` is fixed (`Niagara.UsageImmutable`); its `Settings`, `Parameters` and `Graph` work as for scripts; after its edits the pad is applied (its users refresh), then the system compiles once.
- A stack module or dynamic input uses a pad with `"Script": "ScratchPad:<name>"` (the system's pad of that name, else the emitter's); pad modules have no `Version`.
