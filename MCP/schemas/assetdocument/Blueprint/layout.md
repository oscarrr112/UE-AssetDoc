# Blueprint reference: Layout and comments

- Layout: a node's `Position` (`{"X", "Y"}`, its top-left corner) is where the editor draws it; apply never moves an existing node the document leaves without one. A node apply creates without a `Position` is laid out the way people lay out Blueprint graphs: exec flow runs left to right (a node's column is its longest exec path); every event or function entry starts its own horizontal band, bands stacked top to bottom in document order; a node's first exec output continues its row, each further output (Branch's False, Sequence's Then 1, a cast's Cast Failed) opens a row below, in pin order; pure (data) nodes sit left of the node that first uses them, in input pin order; sizes are the editor's own, so laid-out nodes overlap nothing. Nodes added to a graph that already has nodes go next to the node they link to (same offset as in a fresh layout, moved down until they clear every node); a new event's band goes below everything. Hand-tuned graphs: state `Position` on every node. `"Layout": "Auto"` on a graph lays out again every node without a `Position` (nodes with one stay; the graph's first laid-out node keeps its place and the others are arranged around it); applying it again changes nothing, and extract does not write it. It works on a collapsed graph in `Subgraphs` too, and the profiles that share these graphs (Widget, Anim and Level Sequence Director Blueprints) take it the same way. Diff reports a relayout that would move nodes at `<graph path>/Layout` (with the moves), so a document whose only change is `"Layout": "Auto"` is applied, not skipped.
- Comments: a node's `Comment` is its comment bubble text; `"CommentBubbleVisible": true` pins the bubble open (the bubble's toggle; extract writes it when shown). A comment box (the editor's Add Comment) is `{"Id": "Box", "Action": "K2:Comment", "Comment": "Movement", "Position": {"X": -40, "Y": -80}, "Size": {"Width": 640, "Height": 320}, "Properties": {"CommentColor": {"R": 0.1, "G": 0.5, "B": 0.9, "A": 1.0}, "FontSize": 18, "bCommentBubbleVisible_InDetailsPanel": true, "bColorCommentBubble": false, "MoveMode": "GroupMovement"}}`; a new box gets the editor's defaults (Editor Preferences > Graph Editor) for the `Properties` it leaves out, an existing box keeps them. `Size` is only for comment boxes (`Graph.NodeNotResizable` elsewhere). Moving or resizing a box moves none of the nodes in it (they keep their own `Position`s); automatic layout neither moves nor wraps boxes, and lays nodes out as if boxes were not there.
