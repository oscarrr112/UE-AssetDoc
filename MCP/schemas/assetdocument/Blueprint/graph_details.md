# Blueprint reference: Graph details and Validate

- Collapsed graph: a node `{"Id": "Setup", "Action": "K2:Composite", "Name": "Setup"}` plus a subgraph `{"Name": "Setup", "Owner": "Setup", "Signature": {"Inputs": [...], "Outputs": [...]}, "Nodes": [...], "Links": [...]}`; the subgraph's `Entry` / `Result` are its tunnel nodes, and its `Signature` makes the collapsed node's pins (built before the parent graph's links). Renaming the node renames the graph.
- A function may have further return nodes (the editor's extra "Return Node"): declare each as `{"Id": "EarlyReturn", "Implicit": "result"}`; they share the signature's outputs. A link or pin override on a struct member pin (`"Location:ReturnValue_X"`) splits the struct pin, as the editor's "Split Struct Pin" does. A function graph named after an overridable parent or interface function is created as that override, with the parent's signature: its `Signature` Inputs/Outputs fail with `Graph.UserPinsUnsupported` naming the parent function (`AActor::ReceiveHit`; an event is placed with `K2:Event:...` in the EventGraph). Pick another name for a function of your own.
- Validate checks this read-only, on the existing Blueprint or (a new one) on a transient Blueprint of its `ParentClass` (also for Widget and Anim Blueprints, in their K2 graphs; a `K2:ComponentBoundEvent:...@<component>` of a component the document lists as its own is left to Apply, which adds the component first), together with every node key (`Graph.ActionNotFound` with suggestions) and pin name (`Graph.PinNotFound` listing the pins), and reports all problems at once; it judges nodes whose pins the document does not shape (not the Blueprint's own members, implicit nodes, class picks, user pins or properties). Apply checks every node and link, stops at the first failure and reports the other problems Validate's check finds with it.
- A child Blueprint's function override or overridden event has a parent call (`K2:CallParentFunction:<parent class>:<function>`) only when the document lists it (the editor's placeholder parent call is removed with the placeholder event); a custom event with no parameters may state `"Inputs": []`.
- Only Blueprint-callable functions have nodes: a C++ function that is not a `UFUNCTION(BlueprintCallable)` (NiagaraComponent `DeactivateImmediate`) is not in the editor's palette either and fails with `Graph.ActionNotFound` naming the callable functions like it (`Deactivate`).
- Pure functions (`K2_GetRandomReachablePointInRadius`, getters) have no exec pins; impure getters (`GetCurrentLevelName`) need theirs wired: an unwired one is pruned at compile and Apply warns `Graph.PrunedNodeValueRead` at the pruned node (its value would be the default).
