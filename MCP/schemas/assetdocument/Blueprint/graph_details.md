# Blueprint reference: Graph details and Validate

- Node identity: a document node is the live node with its `NodeGuid`; without one, the node last applied with the same `Id` and `Action` (extract writes both back, so an extract with the `NodeGuid`s deleted still names every node); else the one node of its `Action` on both sides. A change of Ids alone, nodes matched by `NodeGuid`, is stored by the next apply that changes the graph; a node placed or pasted in the editor has no recorded Id until then. `duplicate_asset` keeps the Ids and Actions on the copy's nodes; the copy's nodes get new `NodeGuid`s (as the editor's Duplicate gives them), so edit a copy from its own extract or without `NodeGuid`s. The Content Browser's own Duplicate keeps no Ids: extract the copy before editing it by Id. Two nodes that only a shared `Action` could name (two Print String nodes written without `NodeGuid` before any apply recorded their Ids) are removed and placed anew, which loses what the document does not carry (a disabled node's Enabled State), and Apply warns `Graph.NodeRecreated` at each new node: keep the `NodeGuid`s of an extract to edit such nodes.
- Collapsed graph: a node `{"Id": "Setup", "Action": "K2:Composite", "Name": "Setup"}` plus a subgraph `{"Name": "Setup", "Owner": "Setup", "Signature": {"Inputs": [...], "Outputs": [...]}, "Nodes": [...], "Links": [...]}`; the subgraph's `Entry` / `Result` are its tunnel nodes, and its `Signature` makes the collapsed node's pins (built before the parent graph's links). Renaming the node renames the graph.
- A function may have further return nodes (the editor's extra "Return Node"): declare each as `{"Id": "EarlyReturn", "Implicit": "result"}`; they share the signature's outputs. A link or pin override on a struct member pin (`"Location:ReturnValue_X"`) splits the struct pin, as the editor's "Split Struct Pin" does. A function graph named after an overridable parent or interface function is created as that override, with the parent's signature: its `Signature` Inputs/Outputs fail with `Graph.UserPinsUnsupported` naming the parent function (`AActor::ReceiveHit`; an event is placed with `K2:Event:...` in the EventGraph). Pick another name for a function of your own.
- Validate checks this read-only, on the existing Blueprint or (a new one) on a transient Blueprint of its `ParentClass` (also for Widget and Anim Blueprints, in their K2 graphs; a `K2:ComponentBoundEvent:...@<component>` of a component the document lists as its own is left to Apply, which adds the component first), together with every node key (`Graph.ActionNotFound` with suggestions) and pin name (`Graph.PinNotFound` listing the pins), and reports all problems at once; it judges nodes whose pins the document does not shape (not the Blueprint's own members, implicit nodes, user pins or properties; a class picked on a function's pin keeps its other pins judged, so Select Class's `ReturnValue` into Apply Damage's `DamageTypeClass` fails with `Graph.ConnectDisallowed` already in Validate). In a function whose `Signature` says `"Const": true`, a getter of the Blueprint's own member variable linked into a by-reference input that is not const (Normalize In Place's `A`) is the warning `Graph.ReadOnlyReference` at the link: the compiler refuses a read-only value there. Validate does not compile the Blueprint: other compile errors show at Apply. Apply checks every node and link, stops at the first failure and reports the other problems Validate's check finds with it.
- A new Actor Blueprint's disabled placeholder events (the editor's grey BeginPlay, ActorBeginOverlap and Tick) are nodes like any other: extract writes them with `"Ghost": true` and their `Position`, and a graph's `Nodes` list that leaves one out removes it (the editor's own Delete; they compile to nothing), also for a document written before they were extracted: Validate and Diff list such a removal. A new Blueprint whose document lists its EventGraph has only the listed nodes. A listed `K2:BeginPlay` without `Ghost` (or one the document links) is the placeholder made a real event; `"Ghost": true` on a new node places it as a placeholder.
- A child Blueprint's function override or overridden event has a parent call (`K2:CallParentFunction:<parent class>:<function>`) only when the document lists it (the editor's placeholder parent call is removed with the placeholder event); a custom event with no parameters may state `"Inputs": []`.
- A custom event's Details settings are its `Properties`: `Replication` (`"None"`, `"Multicast"`, `"Server"` = Run on Server, `"Client"` = Run on owning Client), `Reliable`, `CallInEditor`, `Deprecated`, `DeprecationMessage`. Extract writes the ones that differ from a new event's; an omitted setting is kept. An event that overrides a parent's event has the parent's replication (a different value fails with `Graph.PropertyNotEditable`).
- Any node's Details panel settings are its `Properties`, written when they differ from a new node's (Switch on String `PinNames` and `bIsCaseSensitive`, Input Key `bShift`, Math Expression, ...); an omitted setting is kept. On Make / Break Struct, `HiddenFields` lists the member pins unchecked in Details (`[]` shows all).
- An Add Component node (the palette's "Add Static Mesh Component", ...) has `TemplateProperties`: the component's Details values (Static Mesh, materials, collision) that differ from the class defaults, as `Components[].Properties` states them; an omitted value is kept. A changed value holding an instanced object is not stated (warning `Graph.UnrepresentedValue`) and is kept by an apply.
- Only Blueprint-callable functions have nodes: a C++ function that is not a `UFUNCTION(BlueprintCallable)` (NiagaraComponent `DeactivateImmediate`) is not in the editor's palette either and fails with `Graph.ActionNotFound` naming the callable functions like it (`Deactivate`).
- Pure functions (`K2_GetRandomReachablePointInRadius`, getters) have no exec pins; impure getters (`GetCurrentLevelName`) need theirs wired: an unwired one is pruned at compile and Apply warns `Graph.PrunedNodeValueRead` at the pruned node (its value would be the default).
- Function `Signature` Details flags beyond the main list: `Exec`, `ThreadSafe`, `UnsafeDuringActorConstruction`, `Deprecated` + `DeprecationMessage`, `CompactNodeTitle`, `InstanceColor` (`{"R", "G", "B", "A"}`). A macro graph's `Signature` holds its Details metadata: `Category`, `Tooltip` (Description), `Keywords`, `CompactNodeTitle`, `InstanceColor`. These are kept as they are when omitted; state `false` / `""` to clear one. Extract writes them when not default.
- A node's `Enabled`: `"Disabled"` / `"DevelopmentOnly"` / `"Enabled"` (right-click Enable / Disable); extract writes a choice the user made (a node keeping the state it was placed with, such as a Development Only Print String, has none), an omitted one is kept, and a stated one is set as the user's choice. On a cast, `Properties: {"Pure": true}` is "Convert to pure cast".
- Async action nodes (Async Load Game From Slot, a gameplay ability task such as Play Montage And Wait) are keyed by the factory class and function, as the palette lists them: `K2:AsyncAction:/Script/Engine.AsyncActionHandleSaveGame:AsyncLoadGameFromSlot`, `K2:LatentAbilityCall:/Script/GameplayAbilities.AbilityTask_PlayMontageAndWait:CreatePlayMontageAndWaitProxy`; the older `K2:AsyncAction:<class>` still names a node kept by its `NodeGuid`, or a class with one factory function.
