# Material reference: Engine materials, follow-ups, error codes

- Engine and plugin materials (`/Engine/...`) are read-only: `inspect_asset_document_target` gives their facts (`MaterialParameters`, `Compile`) and `extract_asset_document` their graph document (`read_only: true`). To edit one, copy it into `/Game` (`duplicate_asset`, or apply the extract with a new `/Game` `Target` and `Action: Create`) and edit the copy.
- A named reroute declaration's `NodeColor` is always extracted because a new one gets a random color; omit it to keep the current color. A Details edit runs the editor's follow-ups: renaming a parameter renames the other nodes of that parameter; changing a parameter's default, group or sort priority updates every node of that parameter; changing `AttributeSetTypes` / `AttributeGetTypes` on Set/Get Material Attributes adds or removes its pins (links to a removed pin go).
- Object names ignore letter case, so two keys that differ only by case (`DropS` / `Drops`) fail with `Document.DuplicateKey` naming both (any JSON object of a document: an editor JSON object keeps one of them).
- Connections are checked as the editor checks a wire (`Material.IncompatibleConnection`, e.g. a texture object into a float input), and cycles are refused (`Material.ConnectionCycle`).
- `Material.InteractiveEditRefused` (at `/Body`): the edit or the recompile tried to open an editor dialog that waits for a click (a message box, a picker, a save prompt), which an MCP request cannot answer, so the apply was rolled back. Progress windows (compiling, texture streaming data) do not count. The document is usually not at fault; make that change in the editor.
- Apply works with the asset open in the Material Editor: the editor is closed for the apply and reopened on the result (`Material.EditorReopened`). Edits in the editor that are not applied yet (its Apply button is enabled) refuse the apply before any change (`Material.OpenInEditorUnsavedEdits`): `asset_editor` `close` with `discard_unapplied: true` drops them; `apply_editor` applies them (then `save_assets` and extract again).
- Other errors (at the document path): `Material.InvalidKey`, `Material.InvalidSource`, `Material.ExpressionNotFound` (a source key that does not exist), `Material.PinNotFound` (with the node's pins), `Material.UnknownProperty`, `Material.InvalidPropertyValue`, `Material.NotAuthoredProperty`, `Material.InvalidPosition`, `Material.InvalidParameterGroups`.
- A changed parameter default that existing Material Instances override does not reach them: apply and validate add an Info `Material.DefaultOverriddenByInstances` naming them.
- Not expressible: the constant a legacy pin stores when nothing is connected (`UseConstant`; new nodes use their `Const*` properties instead), the order of the expression list (it only changes texture and interpolator numbering in the generated shader), node selection and the editor's viewport.
